# Smart Money Platform

Реализованный модуль: [`services/data-service`](services/data-service/README.md) — Java-сервис рыночных данных согласно документации в `docs`.

```bash
cp .env.example .env
docker compose up --build
```

После старта API доступен на `http://localhost:8000`, Swagger UI — на `http://localhost:8000/swagger-ui.html`.

Модули SMC-анализа находятся в [`services/smc-service`](services/smc-service/README.md). API сервиса доступен на `http://localhost:8010`, OpenAPI — на `http://localhost:8010/docs`.

Probability Engine, Conflict Resolver и Risk Manager находятся в [`services/decision-service`](services/decision-service/README.md). API доступен на `http://localhost:8020`.

Paper Order Service, Execution Engine и Position Manager находятся в [`services/execution-service`](services/execution-service/README.md). API доступен на `http://localhost:8030`.

Portfolio Manager, Analytics и Monitoring находятся в [`services/analytics-service`](services/analytics-service/README.md). API доступен на `http://localhost:8040`.

Защищённая внешняя точка входа находится в [`services/api-gateway`](services/api-gateway/README.md). Gateway доступен на `http://localhost:8050`, Keycloak — на `http://localhost:8080`. Внутренние порты сервисов опубликованы только для локальной разработки.

Learning Platform находится в [`services/learning-service`](services/learning-service/README.md). API доступен на `http://localhost:8060`, артефакты моделей сохраняются в MinIO.

Offline-эмулятор и управление торговыми активами находятся в
[`services/backtest-service`](services/backtest-service/README.md). API доступен на `http://localhost:8085`.

Интеграция с OKX находится в [`services/exchange-gateway`](services/exchange-gateway/README.md). Сервис доступен на `http://localhost:8070`; автоматическое подключение к бирже по умолчанию выключено.

Frontend Platform находится в [`frontend`](frontend). Интерфейс доступен на `http://localhost:3000` и использует Keycloak Authorization Code + PKCE.

## Инструкция пользователя

### 1. Запуск платформы

Создайте локальный файл настроек и запустите контейнеры:

```bash
cp .env.example .env
docker compose up --build -d
```

Дождитесь запуска сервисов:

```bash
docker compose ps
```

Откройте `http://localhost:3000`. Для локального окружения подготовлены пользователи:

| Пользователь | Пароль | Возможности |
| --- | --- | --- |
| `admin` | `CHANGE_ME` | Управление активами, историей OKX и шаблонами |
| `trader` | `CHANGE_ME` | Запуск и просмотр торговых операций |
| `viewer` | `CHANGE_ME` | Просмотр данных |

Перед использованием вне локальной разработки обязательно измените стандартные пароли в `.env` и Keycloak.

### 2. Добавление торгового актива

1. Войдите как `admin`.
2. Откройте раздел «Бэктест».
3. В блоке управления активами нажмите кнопку добавления.
4. Укажите идентификатор инструмента OKX, например `BTC-USDT-SWAP`.
5. Задайте точность цены, количества и минимальный размер ордера.
6. Сохраните актив и выберите его в списке.

Добавление актива не включает реальную торговлю. Бэктест использует только сохранённые свечи.

### 3. Загрузка исторических свечей OKX

На странице «Бэктест»:

1. Выберите актив и основной таймфрейм.
2. Отметьте таймфреймы для загрузки: M1, M5, M15, M30, H1, H4 или D1.
3. Укажите даты обучения и проверки.
4. В блоке «История OKX» проверьте список выбранных ТФ.
5. Нажмите «Загрузить все свечи за период».

OKX возвращает до 300 свечей за запрос. Для каждого выбранного таймфрейма платформа запускает отдельную параллельную задачу, перемещается назад по истории и
сохраняет только закрытые свечи. Задачу можно поставить на паузу, продолжить или отменить. Её состояние хранится в PostgreSQL, поэтому
незавершённая загрузка продолжится после перезапуска сервиса.

Статус, количество сохранённых свечей и запросов показываются отдельно для каждого таймфрейма. Для расширения истории укажите более
раннюю начальную дату и запустите загрузку снова. Одинаковые свечи при этом не дублируются. Администратор может удалить сохранённый
датасет выбранного актива; актив и результаты прошлых бэктестов при этом сохраняются.

### 4. Управление сценариями

Откройте раздел «Сценарии». Шаблоны хранятся отдельно в JSON и читаются сервисом при анализе и бэктесте.

Администратор может:

- создать новый шаблон;
- изменить правила входа, Stop Loss, Take Profit и необходимые подтверждения;
- включить или выключить шаблон;
- удалить ненужный шаблон.

Исходные шаблоны находятся в [`config/scenario-templates`](config/scenario-templates). При обновлении контейнеров новые стандартные файлы
добавляются автоматически, а изменённые пользователем шаблоны не перезаписываются.

### 5. Обучение и тестовый период

На странице «Бэктест» задайте два непересекающихся периода:

- «Обучение» — свечи, доступные модели до начала проверки;
- «Бэктест» — последующий период, на котором модель проверяется без доступа к будущим данным.

Чтобы обучить локальную модель для конкретного запуска:

1. Включите «Локально переобучить модель только на обучающем периоде».
2. Проверьте, что для обучающего периода загружены все выбранные таймфреймы.
3. Выберите JSON-шаблоны стратегии.
4. Нажмите «Запустить бэктест».

Платформа выполнит временное walk-forward-разбиение, рассчитает accuracy и Brier score и сохранит артефакт модели в MinIO. Локальная
модель применяется только внутри этого запуска. Если локальное обучение выключено, используется подходящая заранее обученная модель,
созданная до начала тестового периода, либо базовые confidence шаблонов.

### 6. Настройка эмуляции торговли

Перед запуском можно настроить:

- начальный капитал, плечо и риск на сделку;
- направление Long, Short или оба;
- минимальный confidence и долю Kelly;
- maker/taker-комиссии и проскальзывание;
- funding и интервал его начисления;
- задержку исполнения;
- шаг цены, шаг количества и минимальный ордер;
- максимальную долю объёма свечи, доступную для исполнения;
- поддерживающую маржу и комиссию ликвидации.

Stop Loss определяется по структуре выбранного шаблона, а Take Profit — по ликвидности и Risk/Reward. Эмулятор учитывает OHLC свечей,
частичные выходы, гэпы, funding, комиссии, проскальзывание, доступный объём и ликвидацию. При одновременном касании Stop Loss и Take Profit
используется консервативный порядок: сначала Stop Loss.

### 7. Запуск и просмотр результата

1. Проверьте актив, таймфреймы, даты, шаблоны и параметры исполнения.
2. Нажмите «Запустить бэктест».
3. Дождитесь завершения фоновой задачи.

Отчёт содержит доходность, максимальную просадку, win rate, profit factor, Sharpe ratio, кривую капитала, сделки, использованные шаблоны и
сведения о датасете и модели. Запуски сохраняются в PostgreSQL и доступны в блоке «Сохранённые запуски».

Доступные действия:

- «Открыть» — показать полный отчёт;
- «CSV» — выгрузить журнал сделок;
- «JSON» — выгрузить полный результат;
- «Сравнить» — сопоставить от двух до десяти выбранных запусков.

### 8. Replay

Откройте `http://localhost:3000/replay` или выберите «Replay» в навигации.

1. Выберите завершённый запуск.
2. Нажмите «Воспроизвести» для автоматического просмотра.
3. Используйте «Пауза», «Назад», «Шаг» или временной слайдер.

Журнал показывает время, найденный сценарий, решение, confidence, виртуальный вход, выход и результат сделки.

### 9. Важные ограничения

- Бэктест не отправляет реальные ордера на OKX.
- Результаты зависят от качества и полноты загруженных свечей.
- Исторический результат не гарантирует будущую доходность.
- Перед бумажной или реальной торговлей следует проверить стратегию на нескольких непересекающихся периодах и разных рыночных режимах.
