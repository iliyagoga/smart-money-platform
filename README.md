# Elliott Wave Platform

Платформа анализа, бэктеста и торговли по волнам Эллиотта.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build --remove-orphans
```

Фронтенд: http://localhost:3000. API gateway: http://localhost:8050.
Keycloak: http://localhost:8080. Существующий realm `smart-money` и имена
базы/томов сохранены для совместимости с данными и учётными записями.

## Структура Эллиотта

Общий детектор находится в `services/backtest-service/src/elliott.py`.
Live-сервис импортирует его как `backtest_core`.

1. ATR ZigZag подтверждает экстремумы без использования будущих свечей.
2. Проверяются импульс волны 1 и глубина/длительность коррекции волны 2.
3. Macro-фильтр и выбранная модель входа подтверждают вход в волну 3.
4. Стоп задаётся структурой, тейки — расстоянием Risk/Reward.
5. Live-сигнал проходит риск-проверку и направляется в исполнение.

CHOCH, пробой P1, ретест и фильтры ATR/ADX/объёма — параметры входа Эллиотта.
В проекте нет отдельного SMC-анализатора, JSON-шаблонов, обучения моделей или MinIO.

## Работа в интерфейсе

В разделе конфигураций задайте таймфреймы Macro > Structure > Entry,
условия волн, модель входа, стоп, тейки и управление капиталом.
В разделе рынка назначьте активу конфигурацию и режим Paper, Demo или Production.

Для бэктеста добавьте актив, загрузите историю нужных таймфреймов, выберите
период и параметры Эллиотта. Расчёт выполняется на сервере; отчёт содержит
волны, сделки, кривую капитала и метрики. Результаты доступны для экспорта.
Портфельный бэктест распределяет общий капитал между активами.
Replay воспроизводит входы и выходы завершённого бэктеста.

### Память PostgreSQL

В Docker Compose PostgreSQL ограничен 3 ГБ (`POSTGRES_MEMORY_LIMIT`), общий буфер — 512 МБ (`POSTGRES_SHARED_BUFFERS`). Для обслуживания выделено до 128 МБ, для одного autovacuum worker — до 64 МБ; параллелизм запросов ограничен двумя workers. Это переопределяет автоматическую настройку TimescaleDB по всей памяти хоста. `effective_cache_size=2GB` — оценка для планировщика, а не выделенная память. Изменение этих настроек требует пересоздания контейнера PostgreSQL; том с данными сохраняется. Список истории бэктестов читает только метаданные, без JSON результатов.
