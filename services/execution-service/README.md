# Execution and Position Service

Контур исполнения Elliott для PAPER, OKX DEMO и явно включённого OKX PRODUCTION.

Сервис читает `risk.approved` из Redis Stream consumer group и создаёт идемпотентный
ордер. В PAPER исполнение начинается только на следующей закрытой M1-свече: MARKET
использует её open с проскальзыванием, LIMIT/STOP — соответствующее касание. В DEMO
и PRODUCTION заявки передаются в exchange-gateway; STOP сначала остаётся локальным
триггером и после пересечения отправляется как MARKET, поскольку обычный OKX order
не поддерживает тип STOP.

Position Manager реализует:

- стоп-лосс с консервативным приоритетом внутри свечи;
- полное и частичное достижение целей;
- перенос стопа в безубыток после 1R;
- комиссии maker/taker, проскальзывание, funding и ликвидацию по тем же формулам,
  что Elliott-бэктест;
- ручное полное или частичное закрытие;
- состояния и аудит переходов;
- восстановление открытых ордеров и позиций после рестарта.

REST API: `/orders`, `/positions`, `/trades`. OpenAPI: `http://localhost:8030/docs`.

Перед запуском портфеля в DEMO/PRODUCTION проверяется доступный баланс счёта и
минимальная позиция для исходного распределения тейков. `POST /portfolios/{id}/live`
с `validate_only=true` возвращает расчёт без активации; обычный запуск повторяет
проверку до любых изменений trading_configs. Ошибка любого актива блокирует весь
портфель. PAPER сохраняет прежнюю проверку конфигурации без биржевого расчёта.

Бюджет учитывает долю актива ровно один раз в обоих режимах капитала. Расчёт
использует ограничения инструмента, системные лимиты риска/плеча и актуальную цену
OKX ticker, запрашиваемую через exchange-gateway при каждой проверке. Локальные
свечи и тики для этой проверки не требуются. Объёмы выражены в базовой
монете, число контрактов показано отдельно. У промежуточного тейка количество
округляется вниз, последняя цель получает остаток. Для MOVE_TO_BREAK_EVEN первый
тейк переносит стоп без частичного закрытия, поэтому нужен один выход полного объёма
(кроме приоритетного режима breakEvenAtOneR, при котором сохраняются split TP).

Отчёт показывает минимальную позицию и её тейки, обеспечение по текущей цене,
бюджет риска и максимальное расстояние до стопа для этой позиции. Если обеспечение
превышает бюджет или риск не допускает даже одного шага цены до стопа, запуск
запрещён. Комиссии/проскальзывание в эту оценку обеспечения не включаются. Это не
гарантия исполнимости будущих сигналов: точный вход и стоп появятся позднее;
при нехватке объёма исходные тейки не заменяются одним выходом.
