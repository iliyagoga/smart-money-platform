# Backtest Service

Детерминированный offline-эмулятор платформы. Он читает только заранее сохранённые закрытые свечи из TimescaleDB и не подключается к
Execution Engine или бирже, поэтому не может выставить реальный ордер.

## Датасет

Запрос задаёт `train_from`, `train_to`, `test_from`, `test_to`. Периоды обязательны вместе и проходят строгую проверку:

```text
train_from < train_to < test_from < test_to
```

При локальном переобучении явное разделение обязательно. Модель обучается только на train-периоде, после чего её состояние фиксируется и
используется на test-периоде. Без локального переобучения выбирается указанная `model_version` или последняя версия, созданная до начала
тестового периода. Если подходящей модели нет, применяется детерминированная базовая оценка.

## Эмуляция

- свечи всех выбранных ТФ объединяются в один хронологический поток;
- используется тот же `AnalysisPipeline` и тот же JSON `ScenarioManager`, что в live SMC Service;
- вход возможен только на следующей свече после решения и при касании зоны входа;
- Stop Loss строится за структурной границей и после фактического исполнения расширяется минимум до 0,3%;
- RR-цели пересчитываются от фактической цены исполнения и скорректированного Stop Loss;
- порог подтверждения по умолчанию равен 0,5 и может быть изменён в настройках;
- локальная модель обучается только на сценариях с фактическим входом и определённым исходом; её статистика калибрует, а не заменяет структурный confidence;
- размер позиции рассчитывается от риска и дробного Kelly с ограничением плеча;
- учитываются комиссия, проскальзывание, funding, gap, частичные цели, безубыток и ликвидация;
- при неоднозначной OHLC-свече используется консервативный приоритет неблагоприятного исполнения;
- сохраняются журнал решений, виртуальные сделки, распределение по шаблонам, модель и границы датасета.

Основной API: `POST /backtests`, `GET /backtests/{id}`, `GET /backtests/{id}/export`.
