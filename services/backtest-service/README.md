# Elliott Backtest Service

Сервис выполняет только стратегию `ELLIOTT` на сохранённых закрытых свечах.
Основной алгоритм — `src/elliott.py`: ATR ZigZag, проверка волн 1–2,
подтверждение входа в волну 3, структурный стоп и цели по Risk/Reward.

Запрос `POST /backtests` содержит актив, `test_from`, `test_to` и конфигурацию
`config.elliott`. При указании периода обязательны обе границы и
`test_from < test_to`. Таймфреймы Entry, Structure и Macro добавляются
автоматически; должно выполняться Entry < Structure < Macro.

Расчёт учитывает комиссии, проскальзывание, funding, шаг цены и количества,
частичные выходы, безубыток, риск-лимит и выбранное использование плеча.
Результаты, сделки и кривые капитала хранятся в PostgreSQL.
Обучения моделей и отдельного хранилища артефактов нет.

API: `POST /backtests`, `GET /backtests/{id}`, `GET /backtests/{id}/export`.
Порт: 8085 снаружи, 8080 внутри контейнера.

История отчётов хранится 48 часов после завершения (для старых записей без даты
завершения — после создания). Завершённые, отменённые и неудачные запуски
удаляются при старте и далее раз в минуту; активные и ожидающие сохраняются.

`POST /portfolio-backtests` принимает название, общий `initial_capital` и
список `assets` с `allocation_percent` и обычным запросом `request` бэктеста.
Все активы используют один период. Нераспределённый капитал остаётся денежными
средствами. Родительский запуск и дочерние расчёты сохраняются на сервере и
восстанавливаются после рестарта.

Общая кривая капитала синхронизируется по времени. Отчёт содержит вклад активов,
объединённые сделки и просадку портфеля. Ошибка дочернего прогона не превращается
в частичный успешный отчёт. Бэктест не отправляет ордера на биржу.
